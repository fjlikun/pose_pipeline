# 实际验证记录

本次使用 Python 3.11+ 环境与 Blender 5.2.4 LTS。此记录不是对所有绑定/Blender 版本的兼容承诺。

- `python -m unittest discover -s tests -v`：9 项通过，包括坐标变换、缺失帧、分数时间、非有限数据、错误 schema、无成功帧、时间逆序、映射、源文件/输出冲突与已有报告保护。
- 真实历史数据：六份 SAM NPZ 的 `pred_keypoints_3d` 转成独立 schema 1.0 JSON，时间为 0、3、6、9、12、15 秒。原始 actor_template.blend 成功生成 451 帧时间范围的动画 `.blend` 和 FBX。只有六个观测姿态，帧间是线性插值，并非新增逐帧推理。
- 独立审查员重新打开保存后的 `.blend`，在六个观测时间比较 10 根映射骨的实际方向与源 JSON：均通过（所用浮点精度下最大角差为 0°）。确认骨约束全部静音、NLA 为空。
- 独立审查员验证骨架旋转、统一 1.8 倍缩放和 29.97 fps 时间映射通过。
- 提取器 mock 模型 + 真实视频解码生成的 JSON 已与驱动器端到端连通。mock 不等于视频 SAM 精度验证。
- `--render-dir`：使用原有带摄影棚相机/灯光的历史场景和一帧真实关键点，在 Cycles 下生成 1400×1100 PNG，进程成功退出，已实际查看图片。原摄影棚相机针对另一个姿态取景，本测试姿态有明显裁切；这是渲染通路测试，不是最终构图交付。工具不自动调整相机，正式动画需要用户设置能容纳全动作的取景。
- FBX 导出工具成功退出并产生文件；未在其他软件回读或验证蒙皮兼容性。
- 日志中的 Pulse 音频目录和 Blender 缩略图缓存只读警告不影响 `.blend`、FBX 与 PNG 的写入。

插件发布、GPU、完整长视频、多人物、动态根运动、其它复杂控制绑定和跨 DCC 导入未测试。
